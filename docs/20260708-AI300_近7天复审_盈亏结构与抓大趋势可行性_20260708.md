# AI300 近 7 天复审:盈亏结构诊断与"抓大趋势"目标可行性评估

**复审对象:** 《AI300 最近 7 天 Dry-Run 进攻态势执行效果归因报告》(2026-07-01 至 2026-07-08 19:15)
**本轮策略目标变化:** 由"30 天开仓 300–600 次"调整为"**不限制开仓数量,但要求能抓住大趋势**"
**复审方法:** Findings → Evidence → Impact → Recommendation
**评分口径:** 0–100 分制

---

## 0. 结论摘要

1. **目标框架的调整是一次重要且方向正确的修正。** 上一轮复审已经指出"精兵化设计哲学"与"300–600 次/月"的量级目标存在结构性矛盾。本轮把量级目标去掉、改为"抓大趋势",这与系统目前"低频、高选择性"的实际行为模式更加自洽,不需要再纠结 PROBE 层是否能承担走量任务。
2. **但去掉频率目标后,真正的核心问题浮出水面:当前系统的盈亏结构方向与"抓大趋势"完全相反。** 主交易层与 SCOUT 层都呈现"赢小、亏大"的模式——盈利单被 TP1 + 保本止损提前锁死,亏损单则跑满初始止损。这不是"信号选得不够好"的问题,而是**出场架构的问题**,且这个问题比 PROBE 吞吐问题更根本。
3. 用胜率反推盈亏比:主交易层实际胜率 25% 需要盈亏比 ≥3.0 才能打平,当前实际盈亏比只有 **1.36**;SCOUT 层实际胜率 33.3% 需要盈亏比 ≥2.0 才能打平,当前实际盈亏比只有 **0.34**。两层都显著低于各自的打平线,这直接解释了 7 天 -8.5478 USDT(主) / -1.7938 USDT(SCOUT)的净亏损。
4. **LONG 方向在 7 天内主交易 0 笔、SCOUT 仅 2 笔且全部亏损。** 若"抓大趋势"包含捕捉上涨趋势,当前 `SIDE_THRESHOLD_OFFSET_LONG_10.00`(7 天内 2772 次,最大单一拦截原因)的强度需要被重新审视,而不是默认保留。
5. **`FIB_EXTENSION_EXHAUSTION_BLOCK`(856 次,第四大拦截原因)也值得用同样的视角复核**——它的设计初衷是防止追高追空已衰竭的行情,但在"抓大趋势"框架下,需要确认它有没有误伤真正的趋势延续型入场。
6. **组合级敞口诊断(Stage 0)已经上线,这是好消息**,但 `net_beta_exposure_model=not_configured` 说明相关性风险敞口仍未真正建模;当前敞口数字很小(1.6%/1.1%)只是因为几乎没有仓位在运行,不能作为"目标杠杆/仓位下系统安全"的证据。
7. **本轮不建议提高仓位或杠杆。** 在出场架构修复、且实盘验证出正的盈亏比之前,任何仓位/杠杆的提升都只会放大当前已经存在的"赢小亏大"结构。

## 2. 核心发现:盈亏结构与"抓大趋势"方向相反

### 2.1 主交易层:胜率与盈亏比数学

```text
样本: 4 笔完整周期,1 胜 3 负,胜率 = 25.0%

胜: BCHUSDT 90.30 分  +7.0657
负: HYPEUSDT 83.19 分 -6.1561
负: LINKUSDT 72.00 分 -2.3034
负: BCHUSDT 72.75 分  -7.1539

平均亏损 = (6.1561 + 2.3034 + 7.1539) / 3 = 5.2045
实际盈亏比(W/L) = 7.0657 / 5.2045 ≈ 1.36

打平所需盈亏比 = (1 − 胜率) / 胜率 = 0.75 / 0.25 = 3.00

差距: 实际盈亏比(1.36)仅为打平所需(3.00)的 45%
```

### 2.2 SCOUT_MICRO 层:胜率与盈亏比数学

```text
样本: 6 笔完整周期,2 胜 4 负,胜率 = 33.3%

胜: XLMUSDT SHORT 83.30 分 (TP1后保本) +0.2043
胜: XMRUSDT SHORT 88.80 分 (TP1后保本) +0.1605
负: XLMUSDT SHORT 90.69 分 (初始止损)  -0.6051
负: ZECUSDT SHORT 87.75 分 (初始止损)  -0.5576
负: ZECUSDT LONG  90.59 分 (初始止损)  -0.4554
负: XLMUSDT LONG  90.20 分 (初始止损)  -0.5404

平均盈利 = (0.2043 + 0.1605) / 2 = 0.1824
平均亏损 = (0.6051 + 0.5576 + 0.4554 + 0.5404) / 4 = 0.5396
实际盈亏比(W/L) = 0.1824 / 0.5396 ≈ 0.34

打平所需盈亏比 = (1 − 0.333) / 0.333 ≈ 2.00

差距: 实际盈亏比(0.34)仅为打平所需(2.00)的 17%
(与报告给出的 profit_factor=0.16897 完全吻合: 0.3648 / 2.1585 ≈ 0.169)
```

### 2.3 两层共同的模式:赢单被"锁小",输单"跑满"

把两层的盈利单单独拿出来看,会发现一个非常一致的模式:

| 层级 | 盈利单出场方式 | 亏损单出场方式 |
|---|---|---|
| 主交易(BCH 90.30) | TP1 部分止盈 → 剩余仓位保本止损 | 直接初始止损 |
| SCOUT(XLM 83.30) | TP1 部分止盈 → 剩余仓位保本止损 | 直接初始止损 |
| SCOUT(XMR 88.80) | TP1 部分止盈 → 剩余仓位保本止损 | 直接初始止损 |

**没有一笔盈利交易是"让利润奔跑"的**——所有盈利单都在 TP1 之后立刻转为保本,剩余仓位最终以约等于 0 的方式平仓,盈利被锁定在 TP1 那一小段;而所有亏损单都是完整地跑到初始止损。这意味着系统当前的出场架构在结构上**系统性地压低了盈亏比**,与"抓大趋势"(需要让少数大趋势交易贡献远超其他交易的收益)的目标方向正好相反。

### 2.4 按日 near-miss 数量趋势解读

```text
07-01: 0    07-02: 7    07-03: 7    07-04: 14
07-05: 28   07-06: 23   07-07: 16   07-08(半日): 5
```

near-miss 数量在 07-01 到 07-05 持续上升(0 → 28),随后在 07-06 精兵门/质量门收紧后开始下降(28 → 23 → 16),07-08 因为只有半天日志,数字进一步降低符合预期。这个曲线本身有两种可能的解释,需要区分开:

1. **市场机会真的在 07-05 前后增多**,之后因为整体波动率下降,近失信号自然减少;
2. **07-04、07-05 新增的 mission 标签(`NON_RR_HIGH_SCORE`、`TARGETED_LONG_OFFSET`、`SCOUT_ONLY_HIGH_SCORE`)本身扩大了"近失"的记录口径**,使得中段的高计数部分是记录粒度提升的产物,而不是纯粹的市场信号增多。

### Findings

两层盈利交易的出场路径完全一致(TP1 后保本),亏损交易也高度一致(直接跑满初始止损);near-miss 数量的中段峰值可能同时包含真实市场信号和记录口径变化两种成因,报告未做区分。

### Evidence

- 主交易 7 天净 PnL:-8.5478 USDT;SCOUT 7 天净 PnL:-1.7938 USDT,两者均为负,与上述盈亏比不足的数学直接对应。
- 全部 3 笔有盈利记录的交易(BCH 90.30、XLM 83.30、XMR 88.80)出场路径完全相同:`TP1_HIT` → `BREAKEVEN_STOP_HIT`。
- near-miss 计数曲线的拐点(07-05→07-06)恰好与 mission 标签新增(07-04、07-05)和精兵门收紧(07-06)两次配置改动的时间点重叠,单靠现有数据无法分离两种成因。

### Impact

如果这个出场结构不改变,即使未来 PROBE 层吞吐问题被解决、开仓数量增加,系统大概率会持续产生"多笔小赢 + 少笔大亏"或"多笔小赢 + 多笔中等亏损"的组合,净期望值继续为负。这与"抓大趋势、不限制次数"的目标存在根本性冲突——抓大趋势的前提是让极少数正确的交易贡献远超过其他交易总和的收益,而当前架构主动阻止了这一点的发生。同时,如果不区分 near-miss 曲线的两种成因,团队可能误判"市场机会正在变多/变少",从而做出不必要的参数调整。

### Recommendation

1. **把"TP1 + 立即保本"改为"TP1 + 条件性移动止损"**,只有在未达到一定的已实现 R 倍数之前才使用保本止损,达到之后切换为结构化移动止损(跟踪摆动点或 ATR 倍数),让剩余仓位有机会捕捉后续的大趋势延续,而不是提前拍平。

```python
# 建议: 分层退出逻辑,把"保本"与"移动止盈"分开
def manage_exit_after_tp1(position):
    if position.unrealized_R < 1.5:
        # 尚未确认趋势延续,维持保本止损,防止小反转吃掉整笔盈利
        position.stop = position.entry_price
    else:
        # 趋势延续确认,切换为结构化移动止损(而非固定保本)
        position.stop = trailing_structure_stop(
            position, lookback_bars=20, atr_multiplier=2.0
        )
        # 不再提前平掉剩余仓位,让"大趋势"部分的盈利有机会扩大
    return position
```

2. 在正式改动主账本出场逻辑之前,先在 PROBE_TIER / SCOUT 层小仓位验证这套"条件性移动止损"逻辑,用 20–30 笔样本验证盈亏比是否能提升到打平线以上,再决定是否推广到主账本。
3. 把"实际盈亏比 / 打平所需盈亏比"作为每周复盘的核心指标,而不仅是看胜率或净 PnL 的绝对值——胜率和 PnL 会被小样本掩盖问题,盈亏比缺口更能提前暴露结构性风险。
4. 在下一份报告中,把 near-miss 计数按"是否属于新增 mission 标签"拆分统计,分离"市场信号变化"与"记录口径变化"两种成因。

## 3. 80% 胜率目标在"抓大趋势"框架下的重新定位

### 3.1 胜率与盈亏比的一般关系

```text
打平所需胜率 = 1 / (1 + RR)

RR = 0.5  → 打平胜率 66.7%
RR = 1.0  → 打平胜率 50.0%
RR = 1.5  → 打平胜率 40.0%
RR = 2.0  → 打平胜率 33.3%
RR = 3.0  → 打平胜率 25.0%
RR = 5.0  → 打平胜率 16.7%
RR = 8.0  → 打平胜率 11.1%
```

反过来看,如果真的能维持 80% 胜率:

```text
胜率 = 80% 时,打平所需 RR = (1 − 0.8) / 0.8 = 0.25

也就是说,在 80% 胜率下,哪怕平均盈利只有平均亏损的 1/4,
系统整体也已经是正期望值 —— 这在数学上是一个很低的门槛。
```

**这里出现一个需要正视的矛盾:**"抓大趋势"这个描述,本身暗示的是"少数交易贡献大部分收益、多数交易可能只是小赢小亏或被震出场"的模式——这类模式在经典的趋势跟随类策略中,历史上更常见的胜率区间是 **35%–50%**,靠的是极高的盈亏比(让少数大趋势交易的盈利达到平均亏损的 5–15 倍)来实现正期望值,而不是靠高胜率。而 80% 胜率的策略,历史上更常见于**均值回归/高频剥头皮类**策略,这类策略通常目标较小、单笔风报比不高,但依靠高频次和高胜率累积收益。

### 3.2 两种路径都能达到 50%/月,但架构完全不同

| 路径 | 胜率 | 典型 RR | 对出场架构的要求 | 对开仓频率的要求 |
|---|---|---|---|---|
| 高胜率路径 | 70–85% | 0.3–0.8 | 快速止盈,不需要跟趋势跑 | 通常需要较高频次才能积累收益 |
| 趋势跟随路径 | 35–55% | 3–15(靠少数大赢单拉高均值) | 需要移动止损/让利润奔跑,能接受多次小止损 | 频次可以很低,不需要走量 |

当前目标同时写着"胜率 80%+"和"抓大趋势",这两者在架构上要求的出场设计是矛盾的——不能既要求大部分交易快速兑现高胜率,又要求个别交易被放大到"大趋势"级别的盈利。

### Findings

现有目标里的"胜率 80%+"更接近高胜率/均值回归类策略的特征,而"抓大趋势"更接近低胜率/高盈亏比的趋势跟随类特征,两者对出场架构的要求方向相反。

### Evidence

- 第 2 章的数据显示,当前系统的盈利单出场方式(TP1 + 保本)本质上是"快速兑现"式设计,但胜率(25%/33.3%)远低于这种设计所需要的 66–75% 区间。
- 系统本身已经具备"大趋势相关"的组件(历史记忆中的 EMA 趋势上下文打分),说明设计初衷并非纯高频剥头皮,而是希望捕捉结构性行情。

### Impact

如果不澄清"胜率 80%"和"抓大趋势"哪个是主要目标、哪个是参考指标,团队容易在参数调整时反复横跳——一会儿因为胜率不达标而收紧止损(牺牲盈亏比),一会儿又因为想抓大趋势而放宽止损(牺牲胜率),两头都做不好。

### Recommendation

1. 建议把"胜率 80%+"重新定位为**参考指标而非硬性验收标准**,改用"综合期望值"作为主要验收指标:例如"要求 30 天净收益 ≥ 目标值,不限制胜率区间",给团队在胜率和盈亏比之间寻找最优组合的空间。
2. 如果确实希望保留较高胜率(比如 55–65% 作为一个中间目标,而不是 80%),需要相应地把当前"TP1+保本"的出场逻辑保留在多数交易上,但为**少数被明确判定为"大趋势候选"的交易**(例如多周期趋势强共振、ADX/趋势强度指标达到极值)单独启用"让利润奔跑"的出场逻辑,形成两套并行的出场策略,而不是对所有交易使用同一套。
3. 无论选择哪条路径,都应该先用第 2 章提出的盈亏比缺口指标做验证,而不是直接把 80% 胜率当作绝对达标线来倒逼参数。

### 3.3 建议的目标重新表述(供讨论)

为了避免"胜率 80%+"与"抓大趋势"在执行层反复打架,建议把目标表述从单一数字改为一个组合条件,供团队讨论是否采纳:

```text
现表述(存在内部张力):
  胜率 >= 80%,且能抓住大趋势,30 天收益 >= 50%

建议表述(把胜率降级为参考指标,期望值作为主验收标准):
  30 天净收益 >= 50%(主验收标准)
  且 任意滚动 20 笔样本的实际盈亏比 >= 对应胜率下打平线的 1.1 倍(健康度标准)
  且 单笔最大亏损 <= 账户权益的 X%(风控标准,具体数值待定)
  不预设胜率区间,允许胜率在 35%-80% 之间浮动,只要上述条件同时满足
```

这不是要求团队立刻采纳这个具体表述,而是想说明:**把"胜率"从硬性目标改为浮动区间、把"盈亏比达标度"和"净收益"作为主验收标准**,能同时兼容"高胜率快进快出"和"低胜率抓大趋势"两条路径,而不需要提前二选一。

## 4. LONG 方向的结构性缺失与"抓大趋势"目标的冲突

### 4.1 数据现状

```text
7 天内 SIDE_THRESHOLD_OFFSET_LONG_10.00 拦截次数: 2772(全部拦截原因中最高)
7 天内主交易 LONG 开仓数: 0(4 笔主交易全部为 SHORT)
7 天内 SCOUT LONG 开仓数: 2(ZECUSDT LONG 90.59、XLMUSDT LONG 90.20),
                          两笔结果均为 INITIAL_STOP_HIT(负)
```

### 4.2 为什么这与"抓大趋势"直接相关

"抓大趋势"本身没有方向限制——如果 7 天窗口内市场其实存在有意义的上涨阶段,而系统的 LONG 侧被一个固定 +10 分的偏移量结构性抑制,那么无论 PROBE/SCOUT 层如何优化,系统在这段时间里都不可能捕捉到任何一次上涨类的大趋势。这不是"错杀了几个信号"的问题,而是**整层机会集被单向排除**的问题。

### Findings(4.1/4.2)

当前 LONG 方向在主交易层完全没有样本,在 SCOUT 层只有 2 个样本且均为负,不足以支撑"LONG offset 合理"或"LONG offset 过严"的任何结论——目前唯一确定的是,这个参数是否与市场当前实际趋势方向匹配,还没有被验证过。

### Evidence(4.1/4.2)

- `SIDE_THRESHOLD_OFFSET_LONG_10.00` 是 7 天内出现次数最多的单一拦截原因(2772 次),同时也出现在高分(≥85)拦截原因表中(12 次),说明它同样在拦截部分高分信号。
- 历史记忆中曾提到过"Market Breadth Detector"以及"slow-bull detection modes"这类市场状态识别组件,但本报告没有说明当前 Fib/PA 架构中是否仍保留、并连接了这类动态调整机制,还是 `+10` 是一个静态常量。

### Impact(4.1/4.2)

如果 `+10` 是一个未与当前市场状态联动的静态 legacy 参数,它可能是在过去某个偏空头/震荡的市场环境下设定的,并没有随行情演变重新校准,这会导致系统在真正的上涨大趋势中"视而不见",与"抓大趋势"目标直接冲突。

### Recommendation(4.1/4.2)

1. 确认 `SIDE_THRESHOLD_OFFSET_LONG_10.00` 当前是静态常量还是与某个市场状态/趋势强度指标动态联动;如果是静态常量,建议明确其设定依据和最近一次校准时间。
2. 在 PROBE_TIER / SCOUT 层**主动**而非被动地增加 LONG 方向的采样(而不是等待"恰好评分达标"的 LONG 信号自然出现),配合第 2 章提出的移动止损出场逻辑,在 3–4 周内积累至少 15–20 笔 LONG 方向的小仓位样本,再决定是否调整该偏移量。
3. 在此之前,不建议单方面下调该偏移量——当前 2 笔负样本虽然不能证明"过严",但也同样不能证明"应该放宽"。

### 4.3 FIB_EXTENSION_EXHAUSTION_BLOCK 与趋势延续的潜在张力

`FIB_EXTENSION_EXHAUSTION_BLOCK` 是 7 天内第四大拦截原因(856 次),其设计意图是防止在一段行情已经衰竭延展的位置追高/追空。这类过滤器对**均值回归风险**是合理的保护,但在"抓大趋势"的框架下,需要单独审视它是否也误伤了**趋势延续型**入场——真正的大趋势行情经常会突破常规的 Fib 延展位并继续运行,而不会在延展位准时衰竭。

**Findings:** 该过滤器数量级(856 次/7天)足够大,值得单独做一次"事后验证",而不是默认它的拦截都是正确的。

**Evidence:** 报告没有提供 `FIB_EXTENSION_EXHAUSTION_BLOCK` 拦截后的价格后续走势数据,因此目前无法判断其误伤率;但它与 `SIDE_THRESHOLD_OFFSET_LONG_10.00`(同为高频拦截原因)有相似的风险——都是"为了防止追高追空"而设计,但都可能在真正的趋势行情中反向生效。

**Impact:** 如果该过滤器的误伤率较高,它会和 LONG offset 一样,成为"抓大趋势"目标的隐性天花板,且因为拦截量很大(856 次),潜在影响可能比 LONG offset 更广(不区分方向)。

**Recommendation:** 借鉴通用的门控审计方法——对一批被 `FIB_EXTENSION_EXHAUSTION_BLOCK` 拦截的信号,回放其后续 N 根K线的价格走势,统计"如果放行会盈利"的比例(误伤率)。如果误伤率明显偏高(例如超过 30%),建议将该过滤器拆分为两种情景:"逆势追高追空"(继续拦截)与"顺主趋势方向的延续突破"(降低拦截强度或改为仅收紧止损而非完全拦截)。

## 5. 组合级敞口:诊断能力已上线,但风险模型仍未完成

### 5.1 现状

Stage 0 诊断(2026-07-07 起)已经能输出:

```text
2026-07-07: portfolio_exposure=0, open_position_count=0
2026-07-08: portfolio_exposure=0, open_position_count=0
max_total_exposure_pct=1.6
max_same_direction_exposure_pct=1.1
net_beta_exposure_model=not_configured
```

### 5.2 与上一轮复审建议的对照

上一轮复审曾建议新增"组合级敞口守卫",区分**总名义敞口上限**与**净 beta 加权敞口上限**两套约束。本次数据显示:总敞口/同向敞口的监控确实已经上线(这是积极进展),但净 beta 加权敞口模型仍标注为 `not_configured`——也就是说,如果未来 5 个并发仓位恰好集中在高相关标的上(例如此前观察到的 ZEC/XLM 类同步止损模式),当前的监控口径可能无法识别真正的相关性集中风险,只能看到"同向仓位数"这一较粗的代理指标。

### 5.3 简化压力情景测算:当前监控从未见过目标规模的敞口

本周实际观测到的最大敞口(`max_total_exposure_pct=1.6%`,`max_same_direction_exposure_pct=1.1%`)对应的是本周持仓量极低的现实(全周从未同时出现超过 2 个仓位)。用目标参数做一次简化推算:

```text
目标场景: 5 个槽位打满,平均单仓位 25% 仓位 x 4x 杠杆 = 100% 名义敞口/仓位
  总名义敞口 = 5 x 100% = 500%(权益的 5 倍)

若历史上观察到的"同方向聚集"模式重演(例如 5 个仓位中有 4 个同向):
  同向敞口 = 4 x 100% = 400%(权益的 4 倍)

对比本周实测的监控上限:
  总敞口: 500% vs 本周实测 1.6%  —— 约 300 倍量级差距
  同向敞口: 400% vs 本周实测 1.1% —— 约 360 倍量级差距
```

这个对比说明:**当前的敞口监控系统本身没有问题,但它至今从未在接近目标规模的真实场景下被验证过。** 1.6%/1.1% 这两个数字目前更多反映的是"系统很少开仓",而不是"敞口机制在高负载下依然可靠"。

### Findings

组合敞口诊断能力已部分建成(总敞口、同向敞口),但相关性/beta 加权维度仍缺失;当前敞口数字很低(1.6%/1.1%)是因为持仓量本身很小,不能作为"目标杠杆/仓位规模下敞口可控"的证据。

### Evidence

- `net_beta_exposure_model=not_configured` 是报告原文明确标注的状态,不是推测。
- 历史记忆中已经记录过 ZEC、XLM 等标的存在"止损聚集"的模式,说明相关性风险是真实存在过的现象,而不是假设情景。
- 本周实测的最大敞口数字与目标规模下的简化推算相差 300–360 倍量级,说明现有监控尚未经历过任何接近目标负载的真实压力。

### Impact

如果在净 beta 模型完成之前就把仓位/杠杆提升到目标区间(20–30%/3–5x、5 个并发),一旦 5 个仓位恰好集中在高相关标的同一方向上,现有的"同向敞口 1.1%"这类历史低位数字不会给出任何预警,直到实际发生较大回撤才会被发现。

### Recommendation

1. 在提升仓位/杠杆之前,优先完成 `net_beta_exposure_model` 的配置,哪怕先用一个简化的静态 beta 表(为每个交易对手动赋一个相对 BTC 的近似 beta 值)也好过完全未配置。
2. 用历史数据或蒙特卡洛模拟的方式,人为构造"5 个高相关同向仓位同时开启"的压力测试场景,验证组合敞口守卫在这种场景下是否会正确触发限制——因为当前实盘/dry-run 的低活跃度不会自然产生这种测试样本。
3. 敞口上限的具体数值(建议初始 `max_total_exposure_pct` 可参考不超过 300%,`net_beta_exposure_pct` 不超过 150%)应作为一个独立配置项跟踪,并在每份复盘报告中固定输出,便于观察其在放量后的变化趋势。

## 6. HIGH_BETA 信号需要独立于普通 PROBE 的风控参数

### 6.1 数据线索

HYPEUSDT SHORT,评分 83.19,标记为 `HIGH_BETA PROBE`,7 月 1 日开仓,结果 `INITIAL_STOP_HIT`,亏损 -6.1561 USDT——这是 7 天内单笔金额最大的亏损之一,且发生在一个**评分并不低**(83.19,高于本轮 PROBE 最低门槛 75)的信号上。

### Findings

评分门槛的提升(如 07-06 引入的 `score < 75` 禁止主账本 PROBE)能过滤掉低分信号,但不能防止像 HYPE 这样评分尚可、但因标的本身波动性/beta 较高而在正常止损距离内被震出场的情况。

### Evidence

- 7 天内 3 笔非 DIRECT 的主交易亏损中,HYPE(83.19)是唯一一笔亏损金额明显偏大且评分高于新设 75 门槛的样本,说明"提高评分门槛"这一单一手段无法覆盖 HIGH_BETA 类标的的风险特征。
- 高分(≥85)拦截原因表中出现 `HIGH_BETA_PROBE_BELOW_RISK_REWARD_GEOMETRY_MINIMUM_GAP_3.0`(6 次),说明系统已经意识到 HIGH_BETA 信号需要比普通信号更高的 RR 门槛(3.0 而非 2.0),这个方向是对的,但 HYPE 这笔交易发生在该规则收紧之前。

### Impact

如果 HIGH_BETA 标签的信号继续使用与普通信号相同的止损距离和仓位比例计算方式,即使评分门槛再提高,这类标的仍然可能贡献不成比例的大额亏损,进一步拉低第 2 章中已经吃紧的整体盈亏比。

### Recommendation

1. 确认 07-06 之后引入的 `HIGH_BETA_PROBE` 更高 RR 门槛(≥3.0)规则是否已经覆盖了像 HYPE 这类历史上出现过问题的标的,并在下一份报告中专门列出该规则生效后 HIGH_BETA PROBE 的样本表现。
2. 建议 HIGH_BETA 标记的信号除了更高的 RR 门槛外,同时使用略低于常规仓位比例的仓位(例如常规仓位下限的 70–80%),直到该分类下积累出独立的、可信的盈亏比数据。

## 8. 逐条回应报告第 7 节的复审问题

### 8.1 问题一:PROBE 没有恢复为吞吐层,是否是最大结构性瓶颈?下一步应建独立 PROBE_TIER,还是继续精兵化只扩大 SCOUT?

**Findings:** 部分同意。PROBE 吞吐不足是真实存在的问题(`PROBE=3, DIRECT=1`,7 天仅 4 笔),但在本轮"不限制开仓数量"的新框架下,它已经不是最紧迫的问题——第 2 章揭示的盈亏比结构问题更根本,因为即使 PROBE 吞吐恢复,若出场架构不变,更多的开仓只会带来更多"赢小亏大"的样本,净值可能进一步恶化而非改善。

**Evidence:** 7 天内唯一的 DIRECT 交易(BCH 90.30)和唯一表现较好的 PROBE 交易都遵循同样的"TP1+保本"出场路径,说明即便是当前被认为"精兵"的高分信号,也没有从架构上获得让利润奔跑的机会。

**Impact:** 单纯建立 PROBE_TIER 走量而不改出场逻辑,大概率只是把当前的负期望值以更高频次重复,更快消耗资金。

**Recommendation:** 建议按报告 P1 提议建立独立 `PROBE_TIER`,但赋予它双重任务而非单一"走量"任务:(a)验证第 2 章提出的移动止损出场逻辑,(b)在此基础上再评估合理的吞吐水平。两者顺序上,(a)应先于(b)完成。

### 8.2 问题二:低分 PROBE 是否应从"主账本禁止"改为"进入小仓位 PROBE_TIER 验证"?

**Findings:** 同意,且有数据支持这个方向:7 天内 3 笔亏损中有 2 笔(LINK 72.00、BCH 72.75)评分低于新设的 75 门槛,支持"低分不应直接进主账本"的判断。

**Evidence:** 但 HYPE(83.19,高于门槛)同样亏损,说明单纯提高分数门槛不足以解决问题(见第 6 章),分数不是唯一需要过滤的维度。

**Impact:** 如果只用分数门槛作为 PROBE_TIER 的唯一验收标准,未来仍会出现类似 HYPE 这样"评分合格但仍亏损"的样本,团队可能误以为"分数门槛还不够高"而不断上调,却没有触及真正的问题(出场设计、HIGH_BETA 风险)。

**Recommendation:** 低分候选进入 PROBE_TIER 验证,而不是简单禁止——但 PROBE_TIER 的验收标准应同时包含评分、RR 几何、以及第 2 章的盈亏比表现,而不只是"评分达到某个数字"。

### 8.3 问题三:SCOUT 的哪些 mission 应暂停?

**Findings:** 同意暂停 `NON_RR_HIGH_SCORE`(ZEC 两笔均为初始止损)相关的新开仓,仅保留 near-miss 记录。对于 `TARGETED_LONG_OFFSET`,建议不要完全终止。

**Evidence:** 目前所有 SCOUT 亏损样本使用的都是"直接初始止损"而非第 2 章建议的移动止损设计,现在下结论"这个 mission 无效"还为时过早,可能是出场设计的问题而非入场逻辑本身的问题。

**Impact:** 如果现在就永久性关闭 `TARGETED_LONG_OFFSET`,一旦后续证实问题出在出场设计而非入场逻辑,团队将需要重新搭建这条 mission 并重新积累样本,造成不必要的时间损失。

**Recommendation:** ZEC `NON_RR_HIGH_SCORE`:暂停开仓,继续记录 near-miss。`TARGETED_LONG_OFFSET`:保留,但改用第 2 章提出的条件性移动止损出场后再观察 10–15 笔。XMR/ADA 的 watch-only high-score 测试:同意继续观察,样本太少(XMR 仅 1 笔正反馈)不足以做任何决定。

### 8.4 问题四:LONG offset 是否继续保持主规则不变,只扩大观察?

**Findings:** 同意暂不下调主规则(样本太小,2 笔均为负),但见第 4 章——建议**主动**扩大 LONG 方向的小仓位采样,而不是被动等待。

**Evidence:** 当前 LONG 方向的负样本(2 笔)全部使用了"直接初始止损"的出场设计,与主交易/SCOUT 其他亏损样本的模式一致,不能孤立地归因为"LONG 方向本身不行"。

**Impact:** 继续被动等待会让 LONG 方向的样本积累速度更慢,而"抓大趋势"目标本身需要双向能力,这个不确定性会持续拖长。

**Recommendation:** 见第 4 章第 2/3 条建议:确认该参数是否为动态/静态,并在 PROBE_TIER/SCOUT 层主动增加 LONG 采样(使用新出场逻辑),3–4 周后再评估。

### 8.5 问题五:是否需要把 symbol policy 从静态名单升级为滚动评分面板?

**Findings:** 同意,这是本轮和上一轮复审都独立得出的建议,说明这是一个比较确定的改进方向。

**Evidence:** ZEC 案例(黑名单但持续出现高分)、XMR/ADA(watch-only 但样本太少无法判断)都说明静态名单缺乏定期复核机制,容易在市场状态变化后过时。

**Impact:** 不升级的话,类似 ZEC 这样"高分但一直被排除"的标的会持续消耗团队的人工复核精力,却始终没有客观的晋级/降级标准。

**Recommendation:** 支持报告 P3 提出的 7–14 天滚动面板,并建议在该面板中额外加入"实际盈亏比 vs 打平所需盈亏比"这一列(而不只是 PF/胜率/near-miss 数量),因为第 2 章已证明后者能更早暴露问题。

### 8.6 问题六:目标 300–600 次/月是否应拆成阶段目标?

**Findings:** 本轮策略目标已经把"300–600 次/月"替换为"不限制开仓数量,但要求能抓住大趋势",因此这个问题本身的前提已经发生变化,不再需要用频率来设定阶段目标。

**Evidence:** 第 1 章已对比说明新旧框架的差异;第 2 章的盈亏比数据显示,即使频率提升,当前架构下净值大概率仍为负,说明频率从来不是这个阶段该优化的变量。

**Impact:** 如果继续沿用频率类的阶段目标,团队的优化重心会持续偏向"如何让 PROBE 层多开仓",而不是"如何让每一次开仓的盈亏比更健康",与新目标的精神不符。

**Recommendation:** 建议把阶段目标从"频率"改为"盈亏比达标度":例如"下一阶段目标是在任意 20 笔滚动样本中,实际盈亏比达到对应胜率下打平线的 1.2 倍以上",不设开仓数量下限或上限,让系统按信号质量自然出手。这与"抓大趋势"的精神更一致——机会本来就应该是稀疏且不规律出现的。

| 阶段 1:小仓位验证出场逻辑 | 2–3 周 | 验证盈亏比能否达标 | 在 PROBE_TIER/SCOUT 用新出场逻辑运行,不设频率要求 | 任意连续 ≥20 笔样本,实际盈亏比 ≥ 对应胜率打平线的 1.0–1.2 倍 |
| 阶段 2:LONG 方向主动采样 | 与阶段 1 并行 | 验证 LONG offset 是否合理 | 主动增加 LONG 小仓位样本 | 累计 ≥15–20 笔 LONG 样本,足够判断方向性偏差是否合理 |
| 阶段 3:主账本应用新出场逻辑 | 阶段 1 通过后 2–4 周 | 把验证过的出场逻辑用于 DIRECT/PROBE | 保持当前仓位/杠杆不变,只换出场逻辑 | 主账本盈亏比同样达到阶段 1 标准,且组合敞口压力测试(第 5.3 节)通过 |
| 阶段 4:仓位/杠杆分批爬升 | 视阶段 3 结果 | 逼近 20–30%/3–5x 目标 | 每次只调一个变量(仓位或杠杆之一) | 每次调整后至少运行 1–2 周,盈亏比不劣化才继续爬升 |
| 阶段 5:全量运行 + 月度复盘 | 持续 | 对照 50% 月收益目标 | 用净期望值而非单一胜率数字复盘 | 建立长期滚动复盘机制 |

> 核心原则不变:**每个阶段只改一个变量**,且本轮不再以"开仓次数"作为阶段验收标准,而是以"盈亏比相对打平线的比例"作为核心验收标准——这与"抓大趋势、不限次数"的目标定位直接对应。

## 10. 风险与预期校准提示

1. **当前系统处于净亏损状态,不是"增长慢",而是方向为负。** 主交易 7 天 -8.5478 USDT,SCOUT 7 天 -1.7938 USDT。在讨论 50% 月收益目标之前,第一优先级是让盈亏比达到打平线以上,这是比"如何加速盈利"更基础的问题。
2. **"胜率 80%+"与"抓大趋势"在架构上存在张力**,建议团队内部明确这两者的优先级关系(参见第 3 章),避免参数调整时反复拉扯。
3. **组合敞口的低数值目前是"未测试"而非"已验证安全"**,不要把当前 1.6%/1.1% 的敞口数字当作可以放心提高仓位/杠杆的依据(见第 5.3 节的量级对比)。
4. **不建议在出场架构验证完成前调整仓位或杠杆参数。** 仓位和杠杆是风险放大器,在当前"赢小亏大"的结构下提前放大,只会放大亏损而非收益。
5. 本文档中的盈亏比、打平线等计算基于报告提供的事件级 PnL 数据,存在样本量较小(部分层级仅 4–6 笔)的局限性,结论方向可信,但具体数值会随样本增加而调整。本文档不构成投资建议。
