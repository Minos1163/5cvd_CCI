## 二、验收指标口径裁定(回答开放问题①)

### 1.1 Kaiser≥4/5 为何是一个被错误移植的门槛

前置设计报告(`2026-09-27-orthogonal-factor-redesign.md`)最初为**六因子**体系设定"Kaiser 有效维数 ≥4"。五因子裁定报告沿用时机械改为"≥4/5",但这个数字从未针对 p=5 重新论证过。用最简单的等相关模型可以证明这个门槛在数学上近乎不可达成:

对 p 个标准化变量、两两相关系数均为 ρ 的理想化模型,相关矩阵特征值为:

```
λ₁ = 1 + (p-1)ρ        (重数 1)
λ₂ = ... = λₚ = 1 - ρ   (重数 p-1)
```

当 p=5 时,要让 `λ₂...λ₅` 这 4 个特征值同时 >1,需要 `1-ρ > 1`,即 **ρ < 0**——也就是说,"Kaiser≥4/5" 这个数字,**按最简单的对称模型推导,要求绝大多数两两相关系数为负**,而不是接近 0。这不是"更正交",而是一种特定的负相关结构,不应作为"正交设计成功"的判据。

**结论**:Kaiser≥4/5 门槛本身存在数学移植错误,不是五因子体系没做好,而是这把尺子量错了对象。实测 Kaiser=2(特征值谱 1.3389/1.0848/0.9949/0.9215/0.6600,第三个 0.9949 距 1 仅差 0.005)在这个认识下是**合理甚至良好**的结果,不构成设计缺陷证据。

### 1.2 "前 2PC 累积解释方差 ≤40%" 同样存在先天偏误

对 p=5 个完全独立(两两 r=0)的标准化变量,PCA 退化为原始 5 个单位特征值(λ=1,无偏好方向),此时任意"前 2 个"的累积占比恰好是 **2/5 = 40%**——这是**唯二可能达到 ≤40% 的情形之一**(另一种是出现负相关结构进一步压低头部占比,但那同样不是"正交"的本意)。只要真实数据存在任何非零的相关结构(哪怕每一对都 <0.30 的"安全"范围内),排序取"前 2 名"这个动作本身就会系统性地把累积占比推高过 40%——这是对特征值做降序排序后取头部求和的固有偏误(类似"5 个近似独立的随机数,取最大的 2 个求和,期望值天然高于总和的 40%"),而不是相关性强弱的直接反映。

**结论**:48.47% 这个实测值,在"两两 \|r\| 已全部 <0.30"的前提下,**不能单独作为失败证据**,需要用更严谨的方法区分"排序偏误"与"真实冗余结构"两种来源。

### 1.3 裁定:改用双层验收框架

| 层级 | 指标 | 性质 | 门槛 |
|---|---|---|---|
| **硬门**(决定因子是否可用于决策) | 两两 \|Pearson r\| 最大值 | 直接对应线性加权评分中的"重复计权"风险,与业务目标直接相关 | ≤ 0.30(已达标:0.2647) |
| **硬门** | 单因子零值占比 | 直接对应"档位坍缩/因子失效"风险 | ≤ 15%(F4 未达标:31.1%,见第二节) |
| **参考指标**(监控,非否决) | Kaiser 有效维数 | 对 p=5 不再设固定数字门槛,只跟踪趋势(若未来某特征值显著跌破 0.5,提示该因子可能被其余因子线性预测,需重新审查) | 无硬性数字,记录留痕 |
| **参考指标**(监控,非否决) | 前 2PC 累积解释方差 | 同上,改用下方的 parallel analysis 做显著性判定,而非固定百分比 | 见 1.4 |

### 1.4 建议引入 parallel analysis(供 Task S 实现)

```python
# 伪代码:对每个因子独立置换(shuffle)打断因子间的真实关联,
# 但保留每个因子自身的边际分布,重复 N 次得到"纯噪声"下的
# 前 2PC 占比零假设分布,再把实测 48.47% 放进去比较分位数
null_top2_shares = []
for _ in range(1000):
    shuffled = {name: np.random.permutation(values) for name, values in factor_values.items()}
    pca = PCA(standardize(shuffled))
    null_top2_shares.append(pca.explained_variance_ratio_[:2].sum())

observed = 0.4847
p_value = mean(s >= observed for s in null_top2_shares)
# p_value 显著小(如 <0.05)才说明实测占比确实高于"纯排序偏误"能解释的范围,
# 才构成"存在未被两两相关捕捉到的冗余结构"的证据
```

该检验结果将决定是否需要进一步排查 F1×F2(r=0.2647)与 F2×F5(r=-0.2071)这两对相关性背后的具体机制,还是可以认定当前结构已经"足够正交,可进入 P2"。

### 1.5 本次实测数据在新框架下的最终判定

用本报告裁定的双层框架重新评阅 `2026-10-04-WINATTR` 给出的 10,685 样本实测结果:

| 指标 | 层级 | 实测 | 判定 |
|---|---|---:|---|
| 两两 \|r\| 最大值 | 硬门 | 0.2647 | ✅ 通过 |
| 单因子零值占比最大值 | 硬门 | 31.1%(F4) | ❌ **不通过**——是本次唯一真正的硬门失败项 |
| Kaiser 有效维数 | 参考 | 2 | 不作数,原因见 1.1 |
| 前 2PC 累积方差 | 参考 | 48.47% | 需 parallel analysis 复核(Task V 实施后补齐),暂记为"待定" |
| F2×F3 相关性(收敛预案触发线) | 专项 | 0.0044 | ✅ 远低于 0.30,F2/F3 合并预案**不触发** |

**结论**:五因子体系在"两两正交"这一核心硬门上**已经通过**,唯一需要修复后才能重新评审的是 **F4 零值占比**(第二节)。`2026-09-27-FACTOR` 这一 P0 的状态应维持 IN_PROGRESS,阻塞原因从"验收口径未裁定"更新为"等待 Task F4-FIX 完成后的二次验收",而不是继续笼统地标注"未通过"。

## 三、F4 零值 31% 修复方案裁定(回答开放问题②)

### 2.1 问题复核

当前实现:

```python
vol_score = clip(1 - abs(atr_pctile - 0.60) * 2.5, 0.0, 1.0)
```

系数 2.5 使 `|atr_pctile - 0.60| ≥ 0.40` 时直接硬夹到 0,即 `atr_pctile ≤ 0.20` 的全部区间都不携带任何信息——实测零值占比 31.1%,是五个因子中唯一超出 ≤15% 硬门的一个,也是五因子体系里有效档位最少的(352 档,其余因子 1,858–5,846 档)。这是**真实设计缺陷**,不是验收指标问题(与第一节讨论的 Kaiser/PC 问题性质不同,需要单独处理)。

### 2.2 候选方案

| 方案 | 公式 | 优点 | 缺点 |
|---|---|---|---|
| A:降低线性系数 | `clip(1 - |p-0.6| × 1.0, 0, 1)` | 改动最小,仍是分段线性,易解释 | 仍存在硬夹断点(在 `|p-0.6|≥1.0` 时,但因 p∈[0,1] 这个条件几乎不可能触发,相当于变成处处非零,但牺牲了峰值区分度——两端评分过于接近,失去"倒 U"的集中度) |
| B:高斯型衰减 | `exp(-((p - 0.6)²) / (2σ²))`,建议起始 σ=0.25 | 渐近趋 0,无硬夹断点,零值占比理论上趋近 0%;形状仍保留"中部达峰、两端衰减"的设计意图 | 引入新超参数 σ,需要数据校准;计算成本略高(可忽略) |

**σ=0.25 的量化效果(供参考,非最终值)**:

```
p=0.60(峰值)    → vol_score = 1.000
p=0.20 或 1.00  → vol_score = exp(-0.16/0.125) ≈ 0.278(不再是硬 0)
p=0.00          → vol_score = exp(-0.36/0.125) ≈ 0.056(接近 0 但非精确 0)
```

### 2.3 裁定

**采用方案 B(高斯型)**,但**不直接替换线上影子公式**,按项目一贯的"先影子对照,再切换"纪律执行:

1. P0 影子阶段同时记录**两套** `volatility_regime` 取值(`volatility_regime_clip_v1` 保留现状,`volatility_regime_gauss_v2` 用 σ=0.25 起始值),互不覆盖,写入 `component_points_v2_meta`;
2. 下一窗口(10-04~10-11)跑满后,对比两套取值的零值占比、与前向收益的 IC、以及与其余四因子的两两相关性(确保高斯型改动不会意外抬高与 F1/F5 的相关性);
3. σ 本身也建议做小范围网格(0.20/0.25/0.30)对照,而非直接拍定 0.25,最终取值由 P2 阶段 IC 数据裁决,不在本报告拍板。

### 3.1 两窗口持续出血的量化证据

| 窗口 | 笔数 | notional_pnl | 胜率 | 杠杆 | 场均亏损 |
|---|---:|---:|---:|---|---:|
| 09-16~09-27 | 12 | -116.13 | 16.7% | 3x | -9.68 |
| 09-27~10-04 | 6 | -118.04 | **0.0%** | 3x | -19.67 |
| **合计** | **18** | **-234.17** | **11.1%**(2/18) | 3x | -13.01 |

按 `2026-08-18-纪律`(SAMPLE_SIZE_DECISION_RULES)明文规则"负信号 2 窗口一致可停用",`main_probe` 已满足触发条件——**但"可停用"是许可而非强制**,本报告认为在动用"停用"这一最重手段前,必须先排除一个本窗口新出现的混淆变量。

### 3.2 关键发现:本窗口 main_probe 与方向高度耦合

逐笔核对第一节 1.5 表:

| 通道 | 本窗口笔数 | 其中 LONG | 其中 SHORT |
|---|---:|---:|---:|
| main_probe | 6 | **5(83%)** | 1(17%) |
| main_direct | 5 | 0(0%) | **5(100%)** |

而本窗口整体方向胜率是 **LONG 10%(1/10)/ SHORT 50%(6/12)**——`main_probe` 恰好把本窗口表现最差的方向占了八成以上,`main_direct` 则完全押在表现最好的方向上。这意味着:**本窗口 main_probe 的 0% 胜率,有相当比例可能是"方向混淆"而非"probe 层入场质量系统性更差"**。

### 3.3 但方向混淆不能解释上一窗口的证据——核心裁定依据

把同样的检验放到上一窗口:09-16~09-27 窗口整体方向胜率是 **LONG 15.4% / SHORT 15.0%**——两侧几乎同样差,**不存在方向混淆**(前置诊断报告 1.3 节已明确写"两侧同亏")。在这个"干净"的窗口里:

```
main_probe:  12 笔,场均 -9.68,胜率 16.7%,杠杆 3x
main_direct:  5 笔,场均 -3.76,胜率 20.0%,杠杆 4-5x
```

**main_probe 场均亏损是 main_direct 的 2.6 倍,且杠杆更低**(3x vs 4-5x)——按理杠杆更低、单笔名义敞口更小,场均 $ 亏损应该更小,但实际相反。这说明在排除方向混淆之后,**main_probe 的入场质量问题依然成立**,不能把本窗口的全部 0% 胜率都归因于"碰巧选中了差方向"。

**裁定依据**:两条证据链都指向同一结论但机制不同——上一窗口证明"probe 层本身选的点位更差"(与方向无关),本窗口证明"probe 层本身选的方向也更差"(与点位无关)。两者叠加,构成立即行动的依据,但也说明问题可能有两个独立来源,简单提高单一分数门槛未必能同时解决。

### 3.4 杠杆改动的净效应需先核实三重 Cap 哪个生效

本报告起草时最初的直觉是"main_probe 杠杆 3x→2x,降低放大倍数",但核对 `_notional_cap_diagnostics` 的三重取 min 机制后,这个直觉**未必成立**,必须先说明白,避免给出一个方向错误的建议:

```
raw_notional             = equity × risk_pct / stop_pct              # 与杠杆无关
leveraged_cap_notional   = equity × max_single_trade_risk_pct / (stop_pct × leverage)   # 与杠杆成反比!
remaining_exposure_notional = (symbol_cap - current_symbol_exposure) × equity           # 与杠杆无关
final_notional = min(三者)
```

`leveraged_cap_notional` 与杠杆**成反比**——前置报告原文已明确佐证这一点:"5x 会把名义仓位压到约 1/5"。这意味着:**如果 `leveraged_cap_notional` 恰好是 main_probe 交易的生效上限,把杠杆从 3x 降到 2x,反而会把允许的名义仓位从约 1/3 放大到约 1/2,扩大而非缩小风险敞口**——与直觉相反。只有当 `raw_notional` 或 `remaining_exposure_notional` 是生效上限时,降杠杆才不会产生负面副作用(但此时也不会产生任何正面效果,因为生效上限根本不含杠杆项)。

**结论**:在没有逐笔核实"main_probe 这 18 笔历史交易里,三重 cap 中哪一个是 `binding_cap`"之前,**单纯调整杠杆倍数是一个方向不确定的动作,不应作为"立即执行"的风险收紧措施**。这个核实本身应作为 Task P 诊断的一部分(见 3.5 第四项),而不是在本报告里拍板一个可能适得其反的参数改动。

### 3.5 裁定:分层处置,不做单一动作

| 动作 | 立即执行 | 理由 |
|---|---|---|
| **下调 `probe_risk_pct`**(如 0.0025→0.0015) | ✅ 立即(配置改动,方向明确、完全可逆) | `raw_notional` 与 `risk_pct` 线性正比,且是三重 min 之一——下调它只会让 `raw_notional` 变小或不变,**不存在使最终敞口变大的可能**,是本窗口诊断范围内唯一方向无歧义的收紧杠杆/仓位手段 |
| **main_probe 杠杆倍数本身** | ⏸ 暂不直接改动 | 效果方向取决于历史 binding_cap 分布,需先由 Task P 核实(见 3.4) |
| **提高 PA/Fib/RR 门槛** | ❌ 暂不 | `entry_score` 及其子分量尚未证明有预测力(09-27/10-04 两份报告均明确指出分数与结果无单调关系),在没有 IC 证据支持"哪个分量真正预示 MFE"之前抬高门槛,等同于又一次"拍脑袋",重复了六因子体系当初的错误 |
| **全面停用 main_probe** | ❌ 暂不 | main_probe 并非实验性边车通道(不同于 mirror_ab),是核心成交量来源之一;在未排除方向混淆、未完成专项诊断前全面停用,风险/收益比不明朗;若 Task P 诊断确认问题与方向无关且持续,下一轮评审可重新评估升级为停用 |
| **Task P:main_probe 专项诊断** | ✅ 立即启动 | 见 3.6 |

### 3.6 Task P 诊断范围(建议)

1. **跨窗口方向控制回归**:汇总至少 4 个窗口的 main_probe/main_direct 逐笔数据,用"方向"作为控制变量,检验"通道"这个因子在控制方向后是否仍对 MFE/notional_pnl 有显著解释力;
2. **五因子影子分横向对比**:既然 `component_points_v2` 已在 VPS 落地且本窗口有 10,685 条真实样本,可以直接比较 main_probe 与 main_direct 入场时刻的 F1-F5 取值分布差异(例如:main_probe 的 `order_flow` 是否系统性偏低?),这是六因子 `entry_score` 做不到但五因子影子数据**现在就能做**的分析,不需要等 P2 的 IC 排序;
3. **象限分布核查**:两窗口 main_probe 均主要落在 Q1,是否存在"Q1 本身对 probe 层不友好,但对 direct 层友好"的结构性差异(例如 Q1 入场点位本身偏晚,只有更严格的 DIRECT 门槛能过滤掉劣质 Q1 信号,而 PROBE 的较松门槛放过了大量低质量 Q1);
4. **`binding_cap` 分布核查**(呼应 3.4):逐笔核实 main_probe 历史交易的 `binding_cap` 是 `raw_notional`、`leveraged_cap_notional` 还是 `remaining_exposure_notional`,只有查清这一点,才能判断调整杠杆倍数本身是否值得作为后续动作,或是否应该转而调整 `stop_pct` 相关参数。

## 五、4x 杠杆质量门控上线裁定(回答开放问题④)

### 4.1 样本量复核

`2026-08-31-4XGATE` 的 shadow 设计已落盘(5 单测通过),但按设计文档自身写明的前提——"数值待历史回测校准,遵 20 笔纪律"——需要核查 DIRECT 层级样本量是否已达标:

| 窗口 | main_direct(DIRECT 层主要通道)笔数 |
|---|---:|
| 09-16~09-27 | 5 |
| 09-27~10-04 | 5 |
| **合计** | **10** |

**未达 20 笔门槛**(差 10 笔)。即便本窗口 main_direct 表现亮眼(5 笔 +78.29,80% 胜率),单窗口的强表现**不构成**校准 4x 质量门控具体数值的依据——上一窗口 main_direct 同样是 5 笔但 -18.78(20% 胜率),两窗口合力净值 +59.51,看似转正,但样本量仍然过小,窗口间方差本身就很大(从 -18.78 到 +78.29),用这种波动幅度的数据去校准一个会直接影响实盘杠杆分配的门控,风险过高。

### 4.2 裁定

**暂不上线,继续影子**。具体安排:

1. `scripts/leverage_tier_gate_shadow.py` 保持当前影子运行状态,不接入 `_select_leverage`;
2. 在 `channel_cumulative_tracker.py` 中新增一条按"杠杆层级"(而非仅按通道)聚合的追踪视图,使下一轮报告能直接读出"距 20 笔还差几笔",不必每次手工核算;
3. 预计在当前出手频率下(近两窗口共 10 笔 DIRECT/14 天),再运行 2-3 个窗口(约 3-4 周)可达 20 笔门槛,届时重新提交上线评审。

**出手频率敏感性(供下一轮报告核对实际进度,非承诺)**:

| 假设场奏 | 每窗口 DIRECT 笔数 | 距 20 笔还需窗口数 | 预计达标时间 |
|---|---:|---:|---|
| 维持近两窗口均值(5 笔/窗口) | 5 | 2 | 约 10-18 (2 窗口后) |
| 若方向 regime 持续利好(参考本窗口 5 笔) | 5+ | ≤2 | 约 10-18 或更早 |
| 若回落至首窗口水平(5 笔但负期望) | 5 | 2 | 同上,但需同时关注净值是否持续转正 |

无论哪种场景,**样本量门槛本身不因窗口表现好坏而提前或推迟**——即使某一窗口 DIRECT 表现极佳,也不应以"趋势已经很明显"为由提前解锁,这正是本节裁定要避免的错误。

## 六、entry_score 评分体系转型与方向 regime 门裁定(合并回答开放问题⑤⑥)

### 5.1 为何两个问题应合并处理

开放问题⑤("评分重心应从局部状态质量转向行为确认+regime一致性")与开放问题⑥("是否需要独立市场 regime 门")在本质上是同一个诊断的两种提法:**当前 `entry_score` 完全基于单币种局部结构(K 线/EMA/CCI/Fib/量价),不含任何"大盘当前处于什么状态"的信息**,这正是本窗口方向反转(09-16~09-27 两侧同亏 → 09-27~10-04 LONG 大亏/SHORT 大赚)能够发生、而评分体系对此毫无感知的根本原因。两者的解法应当是同一个:**新增一个独立于现有六因子/五因子评分的市场 regime 层**,而不是在现有评分公式内部硬塞一个新分量。

### 5.2 优先核查:能否复用历史基础设施

项目在更早的 MACD V2 / QuadrantResonance 架构阶段(2026 年 5 月)已经实现过 **BTC Beta Risk Scorer** 与 **Market Breadth Detector**(含 slow-bull 检测模式),用于判断大盘整体风险状态与广度。架构迁移到 Fib-PA 六因子体系后,这部分能力目前的留存状态(代码是否还在仓库中、是否已被移除或只是未接线)**是本建议的首要核查项**——如果这部分基础设施仍然可用,regime 门的工程成本将大幅降低,性质上类似五因子体系里"F5 复用已建成的 CVD 基础设施"的情形;如果已不可复用,则需要重新设计,成本显著更高。**本报告不预设核查结果**,作为 Task R 的第一步任务。

### 5.3 裁定

**不推翻现有评分体系**(六因子/五因子评分继续按既定 P0-P4 路线推进,互不阻塞),**新增一条独立的 regime shadow 门**,按以下阶段执行:

| 阶段 | 内容 |
|---|---|
| R0:基础设施核查 | 核查 BTC Beta Risk Scorer / Market Breadth Detector 代码现状,确认可复用范围 |
| R1:定义最小 regime 信号集 | 候选:BTC 4h/1h 趋势方向与强度、市场广度(多少标的同向)、资金费率市场整体水平(与 F6 的拥挤度维度有潜在重叠,需避免重复建设,见下方提醒) |
| R2:影子记录(不参与决策) | 与五因子 `component_points_v2` 同一批落盘,新增 `regime_context_v1` 字段,仅记录 |
| R3:回溯验证 | 用已有的 09-16~10-04 两个窗口数据做事后验证:regime 信号是否能提前区分"本窗口该以 LONG 为主还是 SHORT 为主"这类方向性结论 |
| R4:评审是否接入 | 达到样本量门槛(沿用 20 笔纪律,但这里的"笔"应理解为"窗口级别"的 regime 判断次数,而非单笔交易,需要在 R1 阶段明确统计单位) |

### 5.4 R1 候选信号集(供 Task R0 核查后细化,本报告不拍定)

| 候选信号 | 测量对象 | 与现有五因子的关系 | 潜在复用 |
|---|---|---|---|
| BTC 1h/4h 趋势方向与强度 | 大盘整体动能,与单币 F1(趋势持久性)同构但作用对象不同(大盘 vs 单币) | 正交(不同标的、不同时间尺度) | 若 BTC Beta Risk Scorer 仍可用,直接复用其评分逻辑 |
| 市场广度(多少标的同向) | 参与度/一致性,现有六因子/五因子体系完全没有覆盖的"横截面"维度 | 正交 | 若 Market Breadth Detector 仍可用,直接复用 slow-bull 检测模式 |
| 资金费率市场整体水平 | 与延后的 F6(单币拥挤度)同源但口径不同(全市场均值 vs 单币) | 与 F6 存在数据源重叠,需第五节提醒的协同设计 | 需新增接口,不可复用现有基础设施 |

**R1 阶段的具体任务**:把以上候选信号做成影子记录字段,不预设哪个最终会被采用——沿用项目一贯"先影子,再用数据裁决"的方法论,不在设计阶段拍板具体信号组合。

**提醒(跨设计一致性)**:`F6`(拥挤度/资金成本,已在五因子裁定报告中延后)与这里提议的 regime 门,在"资金费率"这一数据维度上可能存在重叠——若 R0/R1 发现两者实质上是同一个信号的两种应用场景(F6 是单币评分维度、regime 门是大盘状态维度),应当在同一次接口接入工作中一并设计,避免对同一个新外部依赖(funding/OI 接口)做两次独立的容错设计,重复第五因子裁定报告第二节已经强调过的"新外部依赖需先证明容错"原则。
