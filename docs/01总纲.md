### 二、主文档应该怎么分

你现在最需要的不是一篇大而全的总说明，而是一组能直接喂给 Codex 的“规范文档”。我建议按下面顺序写：

#### 1）`00_project_overview.md`

写清楚项目目标、交易对象、交易周期、非目标。
核心内容：

* 交易标的是市值前 20 主流虚拟币
* 只做 `15m / 30m / 1H`
* `4H` 只做弱参考，不做强制 gate
* 不再使用 watchlist/promotion/floor lift 这类复杂补丁
* 不追求花哨分数，追求可解释、可回测、可实盘

#### 2）`01_strategy_philosophy.md`

把策略哲学一次说死：

* `4H` 只看大方向，不决定入场
* `1H` 决定是否允许交易
* `15m` 决定是否现在开仓
* 任何“弱趋势 + 弱入场”都只允许 probe，不能 direct open
* probe 必须是小仓，且不会被 floor/cap 抬成“假小仓”

这份文档是整个项目的总纲。

#### 3）`03_indicator_spec.md`

把五个指标写成统一规范：

* MACD：趋势/动量
* CCI：过热/过冷与趋势延续
* BOLL：波动带与 squeeze / expansion
* CVD：主动买卖压力
* RSI：超买超卖与回撤质量
* ATR：只做风险，不做方向

这里要明确：每个指标只负责一件事，不允许“既当方向、又当入场、又当风控”。

#### 4）`04_multi_timeframe_rules.md`

这是主策略规则文档，最重要。
要写明：

* `4H`：市场状态过滤器，只输出 `trend_up / trend_down / neutral`
* `1H`：方向确认器，只输出 `long_allowed / short_allowed / no_trade`
* `15m`：入场触发器，只输出 `direct_open / probe / wait / no_trade`
* `30m`：中继确认，只做加权，不做最终裁决
* 三周期冲突处理：高周期优先，低周期只做触发，不可反杀高周期
* `4H` 只是参考，不允许像你旧系统那样变成强 veto

#### 5）`05_entry_state_machine.md`

这是你后续写代码的核心。
状态建议只有这些：

* `FLAT`
* `WATCH_LONG`
* `WATCH_SHORT`
* `PROBE_LONG`
* `PROBE_SHORT`
* `DIRECT_LONG`
* `DIRECT_SHORT`
* `MANAGE_LONG`
* `MANAGE_SHORT`
* `EXIT_LONG`
* `EXIT_SHORT`

要明确：

* 什么条件进入 `WATCH`
* 什么条件升级为 `PROBE`
* 什么条件允许 `DIRECT`
* 什么条件只允许“观望不交易”

你现在最缺的就是这种“状态机，而不是一堆 gate”。

#### 6）`06_position_sizing.md`

这里专门解决你旧系统的仓位契约断裂问题。
要写死：

* `direct` 仓位 = 标准仓
* `probe` 仓位 = 标准仓的 `0.25`
* probe 不能被 floor/cap 抬大
* 如果 probe 小到不满足最小名义额，那就直接跳过，不做硬抬
* 不再允许“算出来是小仓，最后实际变大仓”的行为

这份文档必须明确写出“**宁可不做，也不要扭曲仓位表达**”。

#### 7）`07_risk_and_exit.md`

只保留一套退出逻辑：

* 初始止损：`ATR` 生成
* 止盈：`R multiple` 或 `ATR multiple`
* 移动止损：只允许一种
* breakeven：只允许一种
* 不再同时存在 fixed SL、ATR SL、conflict tighten、MFE breakeven 四套系统

你旧文档里已经指出“固定止损、ATR 止损、conflict tighten、MFE breakeven 多套逻辑互相覆盖，难以验证”，这里就要一次删干净。 

#### 8）`08_backtest_protocol.md`

规定回测怎么跑：

* 样本范围
* 手续费、滑点、最小名义额
* 开平仓撮合方式
* 滚动验证方式
* 如何区分 direct / probe
* 如何统计胜率、最大回撤、回撤恢复期、收益回撤比

#### 9）`09_data_contract.md`

这份文档给 Codex 写数据层时用。
要定义：

* 输入 K 线格式
* 15m/30m/1H/4H 如何对齐
* 缺失 K 线怎么处理
* CVD 的数据源怎么拼
* 如何做时间戳规范化
* 哪些字段是必须字段

#### 10）`13_python_module_spec.md`

这份文档是给 Codex 写脚本的说明书。
每个模块都要定义：

* 函数名
* 参数
* 返回值
* 异常
* 输入输出格式
* 单元测试点
