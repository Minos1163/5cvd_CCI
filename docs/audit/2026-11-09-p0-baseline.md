### 5.2 先后与裁定

`git log` 显示两个文件都只在 `b2a6c2b`（Initial AI300 framework scaffold）与 `8051388`（feat: add dry-run strategy observer）两次提交中被触碰，**无法靠文件级提交时间判定谁后改**。

决定性的证据来自文件结构而非提交时间：`scripts/scaffold_ai300_framework.py` 的 **`:2074` 是一个模板键 `"src/indicators/indicator_spec.py": """..."""`**，即 scaffold 是 `indicator_spec.py` 的**生成器**，`:2092` 那一行是生成器内部的一段模板文本：

- `ast.parse` 遍历该文件，**模块级 `Assign(INDICATOR_NAMES)` 为 0 处**（已实测）；源码中 `INDICATOR_NAMES` 出现 4 次，分别在模板文本内（`:2092`、`:2192`）和 `describe_indicator_rules.py` 模板的 import 段（`:5493`、`:5502`）。
- 因此 `from scripts.scaffold_ai300_framework import INDICATOR_NAMES` 拿不到它，**只能按行首锚定的正则读取**。
- 实际 `src/indicators/indicator_spec.py` 已被手工改为 EMA 版，而生成它的模板仍停在 RSI 版。

**裁定：canonical = `indicator_spec.py` 的 EMA 版（RSI 被 EMA 顶替，且 EMA 占 15m 启用集原第一位）；scaffold 为 03 期冻结契约，不按 live 规格修改。**

### 5.3 由此暴露的真实风险（比"文档过期"更严重）

**重跑 `scripts/scaffold_ai300_framework.py` 会把 canonical 的 `indicator_spec.py` 覆盖回 RSI 版**，且不会报错。这是本项目唯一能静默推翻 live 规格的单点操作。

处置：不做代码改动（P0 不改生成器），改为

1. `tests/test_indicator_name_sources.py::KNOWN_SCAFFOLD_NAME_DIVERGENCE = ({"RSI"}, {"EMA"})` —— 把差异**显式声明**成唯一允许项，任何新增差异都会让测试变红；
2. `test_describe_uses_canonical_names` 直接跑描述器，锁住"描述器输出 == canonical"；
3. `test_scaffold_divergence_is_declared` 用正则读模板，锁住"模板只差这一个指标"。

任何要改指标名集的改动，必须先改 `KNOWN_SCAFFOLD_NAME_DIVERGENCE`，再改实现——防止名源再次静默分叉。

## 6. 出场口径分歧登记（Task 7）

### 6.1 两套默认值

| 侧 | TP 档位 | 分批比例 | 持仓上限 | 来源 |
|---|---|---|---|---|
| paper 主账本 | `1.2R / 2.0R / 3.0R` | `0.40 / 0.35 / 0.25` | 32 根 | `src/observability/exit_spec.py` → `CANONICAL_EXIT_SPEC`（`paper_trading.py` 以别名引用） |
| 离线回测 | `1.0R / 2.0R / 3.0R` | `0.40 / 0.35 / 0.25` | 16 根 | `src/backtest/lifecycle_exit.py:30-32`（`AtrTpExitConfig` 默认值） |

即 `LEGACY_BACKTEST_EXIT_SPEC` 与 `CANONICAL_EXIT_SPEC` 的差异只在 **TP1（1.0 vs 1.2）** 与 **持仓上限（16 vs 32）**，TP2/TP3 与分批比例完全一致。

### 6.2 P0 的决策：只登记，不切换

**回测默认值保持 legacy 不动。** 理由是可复现性而非懒惰：

- `tests/test_lifecycle_exit.py` 有 **6 处** `AtrTpExitConfig(atr_stop_mult=1.0, min_stop_pct=0.01, max_stop_pct=0.01)`（第 21/49/65/81/99/120 行），用例里的高点 101.1 / 102.1 / 103.2 恰好卡在 1.0R / 2.0R / 3.0R。把默认切成 1.2R 后 TP1 需要 101.2，首根 101.1 打不到，这批用例必红。
- 更根本的原因：改默认会让**所有历史离线回测结论静默换口径**，而 P0 的价值恰恰是"可复现"，不是"更准"。

因此 `AtrTpExitConfig` 只新增 `from_spec()` 显式入口，默认值一字未动；差异由 `KNOWN_EXIT_SPEC_DIVERGENCE` 常量在代码里显式登记（而不是藏在文档里），`test_divergence_is_registered_not_hidden` 会守住它。

### 6.3 切换动作与受影响清单（移入 P1-E8）

前置步骤（顺序不能反）：

1. 先把 `tests/test_lifecycle_exit.py` 那 6 处改为显式传 `from_spec(LEGACY_BACKTEST_EXIT_SPEC)`，锁定"它们测的是 legacy 语义"；
2. 再切 `AtrTpExitConfig` 默认值到 canonical；
3. 再重跑所有历史离线结论，把每个数字的变动登记进 `docs/audit/`；
4. 最后才允许删除 `KNOWN_EXIT_SPEC_DIVERGENCE`。

### 6.4 顺带修正的两处"模块级函数拿不到 config"

计划只发现了 `_initial_risk_distance` 是模块级函数。实测 **`_cost_breakeven_timeout`（`paper_trading.py:755`）同样是模块级**，原计划给的改法 `self.exit_config.max_hold_bars // 4` 在那一行根本写不出来（没有 `self`）。

改法：两个函数都改为 keyword-only 可选参数（默认 `None` → 回落模块常量，行为逐字节不变），由 `_update_position` / `_apply_post_tp_stop` 传入仓位的实际配置：

- `_cost_breakeven_timeout(position, close, *, check_bars=None)`
- `_initial_risk_distance(position, tp0_level=None)`
- `_update_max_favorable_r_observed(position, tp0_level=None)`

若不做这一步，"可按仓位覆盖 `max_hold_bars`" 只是纸面能力：`max_favorable_r_observed` 会继续用模块常量 `TP_LEVELS[0]` 反解 R，注入 `tp_levels=(1.5,2.5,3.5)` 时 R 会被算错 25%，而 `trend_trigger_r`（1.2/1.5）的比较会随之失真。
