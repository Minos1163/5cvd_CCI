## 一、裁定结论(先给结论)

1. **因子数量:5 个,不是 6 个。** 保留 F1-F5(趋势持久性、结构位置、赔率几何、波动率状态、真实订单流),**F6(拥挤度/资金成本)延后**,不进入本轮 P0。理由见第二节,核心是工程风险不对称:F5 复用已建成的 CVD 基础设施,边际成本低;F6 需要新增外部接口(funding/OI)且尚无容错设计,与 2026-08-13 审计定位的"接口抖动→永久 DEGRADED→锁死 eligible"是同一类故障模式。
2. **F2 与 F3 不合并。** 两者概念上可分离(自身结构百分位 vs 到对手结构的风险回报),合并与否应由 P1 阶段的真实相关系数裁决,不预先在设计阶段合并,以免过早丢失信息维度。若 P1 实测 |r(F2,F3)| > 0.30,则触发收敛预案(降为 4 因子),预案已写入本报告第九节。
3. **权重方案:先验值仅用于 P0 影子展示,不参与决策**;P2 阶段起并行跑 IC 加权与 PCA 白化等权两套方案做影子对照,依 08-18 MIRROR 先例的方法论(连续多轮对比后择优),而非单次拍板。
4. **F4(波动率状态)采用双重定位:** 同时作为评分因子(非单调、倒 U 型变换)和独立仓位/杠杆调节器(单调递减变换),两者变换函数不同,解决"高波动=低分=不开仓"与"高波动应小仓开"的语义冲突。
5. **不改变任何既有纪律**:不动 live 风控、不解禁黑名单、不全局放宽 RR 门槛、新通道先进独立实验账本、单笔风险预算 0.6% 不动、样本量纪律(10/20/20/2)照旧适用于新因子的权重冻结。

## 二、为什么是 5 个,不是 6 个 —— F6 延后裁定

### 2.1 F5 与 F6 的工程成本不对称

| 维度 | F5(真实订单流) | F6(拥挤度/资金成本) |
|---|---|---|
| 底层数据 | `taker_buy_base_volume` / `taker_buy_quote_volume` **已在 `data_contract.py` 契约中** | 资金费率、持仓量——**当前项目未采集** |
| 计算基础设施 | `src/data/cvd_builder.py::build_cvd`、`src/indicators/cvd.py::cumulative_cvd`/`cvd_delta` **已实现且已接入 `indicator_engine.py`** | 无对应模块,需新建 |
| 新增外部接口 | 无(复用现有 K 线管道) | 需新增 `/fapi/v1/premiumIndex`、`/fapi/v1/openInterest` 两个独立接口 |
| 容错设计 | 复用现有 K 线容错(已验证稳定) | **尚无设计**——独立接口意味着独立故障域 |
| 落地动作 | "接入评分层"(集成工作) | "从零新建"(接口 + 契约 + 容错 + 测试) |

**结论**:F5 是"已建成资产等待接入",F6 是"全新基础设施"。二者虽然在设计文档中并列为"F5/F6",但工程风险量级完全不同。

### 2.2 直接的历史反例:2026-08-13 data_health 事故

`2026-08-13-审计`(已 VERIFIED)记录的根因是:**一次 Binance 拉取抖动 → `data_health` 永久滞留 DEGRADED → `allow_degraded=false` 硬性锁死 `q1_trend_launch` 的 eligible 判定**,导致该通道长期 0 转化,直到周期级重置修复上线才解决。

F6 依赖的 funding/OI 接口是**当前系统完全没有先例的新外部依赖**。如果不预先设计"软失败"(接口异常返回中性默认值、不锁定决策资格),几乎必然复现同一故障模式,只是这次锁死的对象从"某个通道的 eligible"变成"整条评分链路的一个正交因子"。08-13 的教训是**新增外部依赖必须先证明容错设计,再接入决策路径**——本报告据此认为 F6 现阶段不满足接入条件。

### 2.3 与项目既有纪律的一致性

- `2026-08-18-纪律`(SAMPLE_SIZE_DECISION_RULES)明确:不足 10 笔不得"证明有效",不足 20 笔不得"资源倾斜"。F1-F5 尚未产生一笔真实交易数据,在此基础上**再叠加一个全新基础设施维度(F6)**,是对纪律精神的透支——应先把已确定收益/成本比更优的 5 个因子跑通,再评估是否值得为 F6 追加接口投入。
- 前置设计文档 2.2 节本身已把这个问题列为"开放问题 2",并明确指出 F6"需新增接口与容错(接口抖动不得影响决策)"——本报告认为这个前提条件目前不成立,故裁定延后而非否决(见第九节的重新评估触发条件)。

### 2.4 量化视角:5 因子已能覆盖诊断报告识别的全部亏损归因

回顾 `2026-09-27-window-loss-attribution-and-factor-diagnosis.md` 的四维归因:入场质量(MFE 判据)、方向(两侧同亏)、象限(Q1 主导)、退出原因(初始止损 100% 亏损)。F1(趋势)、F2(位置)、F3(赔率)、F4(波动率——新维度,直接对应"3-5x + 高波动=大额亏损"的观察)、F5(真实订单流——直接修复"伪 CVD"病灶)已经覆盖诊断报告指出的全部病因。F6 针对的"拥挤度反转风险"在本窗口的归因证据中**没有直接对应的失血点**(33 笔亏损无一笔被诊断为资金费率/OI 相关),属于"锦上添花"而非"止血必需",优先级理应让位于工程风险更低、证据链更强的 5 个核心因子。

## 三、为什么不把 F2/F3 合并到 4 个

前置设计的开放问题 1 提出:F2(结构位置)与 F3(赔率几何)是否应合并,因为二者都源自同一组摆动高低点。本报告裁定**暂不合并**,理由如下:

| 论据 | 说明 |
|---|---|
| 概念不同源 | F2 回答"价格现在在结构区间的第几百分位"(静态位置);F3 回答"从当前位置到对手结构的距离,相对止损距离的比值"(动态风险回报)。二者都用摆动点作输入,但**输出的市场含义不同**——一个高分不代表另一个也高分(例如:价格正处于区间中段但止损极窏、赔率极佳的情形是完全可能的) |
| 现状证据不支持预判合并 | 现有 PCA(六因子)显示 fibonacci_location 在 PC1 上是唯一反向加载的因子(载荷 +0.470,其余四个动能代理为负),这是因为**旧版 fib 因子随 side 变号、与方向耦合**(r=-0.31)。新设计已把 F2 去方向化,预期相关性结构会发生实质变化,不能用旧因子的相关系数预判新因子的相关系数 |
| 过早合并的代价 | 若合并后的"结构-赔率"复合因子事后被验证两个子维度其实低相关(<0.3),则合并造成了不可逆的信息损失,且无法用同一批 P0 影子数据回溯拆分(需重新采集) |
| 保留可验证的收敛路径 | 不合并不等于放弃这个问题——P1 阶段的正交性验收(见第五节)会用真实数据计算 \|r(F2,F3)\|,若超过 0.30 阈值,立即触发本报告第九节写明的收敛预案,成本远小于"先合并再发现该分开" |

**结论**:先以 5 个独立因子进入 P0/P1,让数据说话,而不是在设计阶段用直觉预先合并。

## 四、最终 5 因子设计规格

设计准则不变:**每个因子测量一个不同的市场机制,数据源可独立获取,连续化档位 ≥10,零值占比 ≤15%。**

### F1 趋势持久性 `TREND_PERSISTENCE`(权重 22)

**定义**:方向 + 强度的连续化测度,替代旧 `trend_ema_context` 的三段离散台阶。

```python
# 唐奇安通道位置(沿交易方向取号,LONG 直接用,SHORT 取 1-pos)
donchian_pos = (close - low_N) / (high_N - low_N)   # N = 20

# EMA200 斜率显著性(连续化,替代 8/0 二值 gate)
ema200_slope_z = (ema200_t - ema200_t_minus_k) / rolling_std(ema200_diff, k)

trend_persistence = 0.5 * donchian_pos_dir + 0.5 * sigmoid(ema200_slope_z)
```

- **数据来源**:现有 15m/1h K 线,无需新接口
- **风控分离**:EMA200 gate(方向大闸)**保留但不进评分**,作为独立风控闸门,避免它靠权重刷分——评分层只回答"趋势有多强/多持久",资格判定单独走
- **替代对象**:`trend_ema_context`
- **代码位置(建议)**:`src/signals/entry_chain_features.py::compute_trend_persistence`

### F2 结构位置 `STRUCTURE_LOCATION`(权重 18)

**定义**:去方向化的位置测度,与方向解耦。

```python
fib_band_pos = (close - swing_low) / (swing_high - swing_low)   # 0-1,不随 side 变号
fib_band_pos_adj = clip(fib_band_pos, 0.0, 1.0)                 # 极端窄幅结构保护
```

- **与旧因子的关键区别**:旧 `fibonacci_location` 打分随 side 变化(与方向耦合,r=-0.31);新版本方向性完全交给 F1 承担,F2 只回答"价格在结构的哪个百分位"
- **数据来源**:现有摆动点检测 + Fib 计算模块
- **替代对象**:`fibonacci_location`
- **代码位置(建议)**:`src/signals/entry_chain_features.py::compute_structure_location`

### F3 赔率几何 `PAYOFF_GEOMETRY`(权重 18)

**定义**:连续化的风险回报测度,修复现状"上限 62.5%"的隐性降权问题。

```python
payoff_r = (nearest_counter_structure_dist - cost_buffer) / atr_stop_dist
# 连续值,不再是 5/3.5/2/0 的四档离散映射
# net_tp1_r >= 1.3 不再是满分天花板——允许超过 1.3 的赔率继续获得更高分
```

- **修复的硬伤**:旧 `risk_reward_geometry` 代码上限只有 5.0(`net_tp1_r >= 1.3 → 5.0` 已是最高档),权重 8 分永远拿不到满分,等效被隐性降权到 62.5%×8=5;新版本连续映射后不存在人为天花板
- **数据来源**:现有摆动点 + ATR
- **替代对象**:`risk_reward_geometry`
- **代码位置(建议)**:`src/signals/entry_chain_features.py::compute_payoff_geometry`

### F4 波动率状态 `VOLATILITY_REGIME`(权重 20)—— 全新维度,双重用途

**定义**:当前策略完全没有覆盖的维度(现状 ATR% 只用于杠杆降档/止损 clamp,未进评分)。

```python
atr_pctile = percentile_rank(atr_pct_14_15m, lookback_days=30)   # 0-1
band_expansion = (bb_width_t / bb_width_t_minus_5) - 1            # 布林带宽扩张率

# 评分分量:倒 U 型——中等偏高的波动扩张(趋势启动期典型特征)得分最高,
# 过低(无跟随)和过高(追涨杀跌/衰竭)都扣分
vol_score = clip(1 - abs(atr_pctile - 0.60) * 2.5, 0.0, 1.0)

# 仓位/杠杆调节分量:与评分分量变换函数不同,单调递减
# 复用 2026-08-31-4XGATE 已落盘的质量门控设计方向
leverage_multiplier = 1.0 if atr_pctile < 0.70 else linear_decay(atr_pctile, 0.70, 1.00, 1.0, 0.4)
```

- **为何是双重用途**:详见第七节,这是回答前置设计开放问题 4 的核心裁定
- **数据来源**:现有 K 线,无需新接口
- **代码位置(建议)**:`src/signals/entry_chain_features.py::compute_volatility_regime`(评分)+ `src/signals/entry_chain.py::_select_leverage`(仓位调节,与 4XGATE 设计共用同一模块)

### F5 真实订单流 `ORDER_FLOW`(权重 22)—— 替换伪 CVD

**定义**:真正的主动买卖失衡,而非"K 线涨跌方向投票"。

```python
taker_ratio = sum(taker_buy_volume for last_12_bars) / sum(volume for last_12_bars)   # 0-1 连续值
cvd_slope_align = cosine_similarity(cvd_delta_slope, price_slope)                      # 连续化,替代旧版 sign match

order_flow = 0.5 * taker_ratio + 0.5 * (cvd_slope_align + 1) / 2   # 归一化到 0-1
```

- **与旧因子的本质区别**:旧 `flow_cvd_confirmation` 的实现是"最近 6 根 15m K 线涨跌方向的有符号成交量投票"(`signed = Σ (+1 if close>=open else -1) × volume`),本质仍是价格方向的代理,与 ema/cci/pa 同源,这正是诊断报告 PCA 中 PC1 四因子同向加载(即"重复计量")的病灶来源
- **能力闲置修复**:项目**已经具备真 CVD 基础设施**——`build_cvd`、`cumulative_cvd`/`cvd_delta` 均已实现并接入 `indicator_engine.py`,`taker_buy_base_volume`/`taker_buy_quote_volume` 已在 `data_contract.py` 契约化。**本因子是"接入"而非"新建"**,这是 F5 优先于 F6 的核心论据(见第二节 2.1)
- **正交论证**:主动买占比与 K 线涨跌方向不同源——阴线但主动买占优(吸筹)是现状代理无法表达的信息,预期能真正拆开 PC1 的四因子捆绑
- **替代对象**:`flow_cvd_confirmation`
- **代码位置(建议)**:`src/signals/entry_chain_features.py::compute_order_flow`,复用 `src/data/cvd_builder.py` / `src/indicators/cvd.py`

### 4.6 参数与边界情况表

设计不能只有"正常路径",必须提前定义退化输入下的行为,避免重演 08-13 式"异常输入 → 锁死"的故障模式:

| 因子 | 关键参数 | 默认值 | 边界情况 | 处理方式 |
|---|---|---|---|---|
| F1 | 唐奇安窗口 N | 20 | `high_N == low_N`(极端窄幅盘整) | `donchian_pos` 未定义 → 回退中性值 0.5,不参与除零 |
| F1 | EMA 斜率回看 k | 10 | 上市初期历史不足 k 根 | `ema200_slope_z` 回退 0(视为无显著趋势),不阻断评分 |
| F2 | 摆动点识别窗口 | ATR 自适应 | 窗口内未识别出有效摆动结构 | 回退至更宽窗口重新识别;仍失败则 F2 取中性值 0.5 并打标 `structure_fallback=true` 供事后审计 |
| F3 | 成本缓冲 cost_buffer | 2×taker fee + 预估滑点 | `nearest_counter_structure_dist ≤ 0`(价格已越过对手结构) | `payoff_r` clip 到 0,不产生负值污染排序 |
| F4 | 分位回看天数 | 30 | 新上线合约历史 <30 天 | 使用可得历史(最少 10 天);<10 天则 `atr_pctile` 回退中性值 0.5 |
| F5 | 订单流窗口 | 12 根 15m | `taker_buy_volume` 字段缺失(数据源抖动) | 回退至最近一次有效值,**不得零填充**(零填充会伪造"无主动买盘"信号,属于比不计分更危险的静默错误) |

**设计原则**:所有边界情况一律回退到"中性值"(通常 0.5)而非"最低分"或"阻断决策",这是与 08-13 教训直接对应的修复——异常输入应该是"信息缺失"而不是"负面信号",更不能升级为"锁死资格"。

## 六、权重方案裁定(回答开放问题 3)

前置设计提出三个候选:IC 加权 / PCA 白化后等权 / 专家先验。本报告裁定**不单选一种,分阶段跑双轨对照**:

1. **P0-P1 阶段**:使用本报告第四节给出的先验权重(22/18/18/20/22),**仅用于影子评分展示,不参与任何实盘决策**,目的是让 P1 的正交性验收(第五节)有一个基准可比较。
2. **P2 阶段(≥20 笔样本)**:并行计算两套权重方案:
   - **方案 A(IC 加权)**:`IC_i = Spearman(因子 i 值, 该笔前向收益 R)`,`w_i ∝ |IC_i|`,并对高相关因子对做正交化残差处理避免重复计权;
   - **方案 B(PCA 白化等权)**:对标准化因子矩阵做 PCA,取正交主成分等权打分,可解释性下降但对小样本噪声更稳健。
3. **P3 阶段**:两套方案与"先验权重"三线并行影子出分(旧评分体系仍照常决策),**不是一次性选边**,而是复用 `2026-08-18-MIRROR` 先例的方法论——连续观察多轮而非单窗口表现,任一方案连续两轮负期望则降级为仅记录。
4. **权重冻结门槛**:任何一套方案要从"影子"转为"参与决策",必须满足 `SAMPLE_SIZE_DECISION_RULES`:样本 <20 笔不得冻结,<10 笔只记录不定性,这一纪律对新因子同样适用,不因是"重构"而豁免。

### 6.1 IC 计算 worked 示例(方法演示,非实盘数值)

以下用示意性伪数据演示计算路径,**不是真实回测结果**,真实数值须由 `Task S` 在完整样本上跑出:

```python
# 伪代码:20 笔影子样本的 IC 计算示意
factor_values = {
    "trend_persistence":   [0.72, 0.31, 0.58, ...],   # 20 个值
    "structure_location":  [0.44, 0.67, 0.20, ...],
    "payoff_geometry":     [1.85, 0.62, 2.10, ...],   # 连续值,无上限
    "volatility_regime":   [0.81, 0.35, 0.59, ...],
    "order_flow":          [0.55, 0.48, 0.71, ...],
}
forward_return_r = [0.9, -1.0, 1.6, ...]   # 对应 20 笔的前向收益(R 倍数)

ic = {
    name: spearman_corr(values, forward_return_r)
    for name, values in factor_values.items()
}
# 示意排序(数值仅为演示排序逻辑,非真实结果):
# order_flow: 0.31 > trend_persistence: 0.24 > volatility_regime: 0.18
#   > payoff_geometry: 0.15 > structure_location: 0.09

weights_ic = {name: abs(v) for name, v in ic.items()}
total = sum(weights_ic.values())
weights_ic = {name: round(100 * v / total) for name, v in weights_ic.items()}
```

- 若某因子 `|IC| < 0.05`,按第九节/前置设计纪律标记为"信息量不足",**不直接剔除**(样本量不足 20 笔时噪声本身就可能压低 IC),而是延长观察窗口至下一个 20 笔周期再复核;
- IC 加权与 PCA 白化两套权重的最终对比,以 P3 阶段三线影子的**实际 payoff**(而非 IC 本身)作为择优依据——IC 只是权重生成的中间工具,不是终裁标准。

## 七、F4 双重定位裁定(回答开放问题 4)

前置设计指出一个真实的语义冲突:如果 F4(波动率)作为普通评分因子,"高波动 = 低分 = 不开仓"的直觉,与"高波动应当小仓位开"的风控直觉互相矛盾——因为不开仓就无需谈仓位。

**裁定:F4 同时承担两个职责,但用两条不同的变换函数,职责互不干扰。**

| 职责 | 输入 | 变换函数 | 输出用途 |
|---|---|---|---|
| 评分分量 | `atr_pctile` | **倒 U 型**(峰值在 60 分位附近,两端衰减) | 进入五因子加权评分,参与开仓/不开仓决策 |
| 仓位调节分量 | `atr_pctile` | **单调递减**(70 分位以上开始线性衰减,复用 4XGATE 方向) | 独立于评分,只影响已决定开仓后的杠杆/notional |

**为什么这样解决冲突而不是二选一**:

- 诊断报告的证据是"3x-5x 杠杆 + 高波动 = 大额亏损被放大",这是**仓位放大效应**,不是"高波动本身就不该开仓"——事实上诊断报告 2.3 节显示 Q3(非主要开仓来源)反而是唯一正 notional_pnl 的象限,说明"波动扩张期"本身不是纯粹负面信号;
- 倒 U 型评分分量表达的市场直觉是:**波动率从低位刚开始扩张,往往是趋势启动的前兆(值得加分)**;**波动率已处于极端高位,往往是衰竭/滑点风险区(该扣分)**——这与 08-31 的三笔大额亏损画像(margin≈486、4x 杠杆、MFE 仅 0.36-0.75R)吻合:那三笔更接近"极端高波动+高杠杆"的组合,而不是"波动刚开始扩张";
- 两条变换函数**输入相同、输出分离**,实现上只需一次 `atr_pctile` 计算,两次不同的映射函数调用,工程成本极低,且两者可独立回测验证,互不掣肘。

### 7.1 两条变换函数的形状对比(示意)

```
评分分量(倒 U 型,峰值在 60 分位):          仓位分量(单调递减,70 分位后衰减):
score                                        multiplier
 1.0┤        ___                              1.0┤────────────┐
    │      ／   ＼                                │            ＼
 0.5┤    ／       ＼                          0.7┤             ＼
    │  ／           ＼                            │              ＼
 0.0┤／               ＼                       0.4┤               ＼____
    └──┬────┬────┬────┬──                        └──┬────┬────┬────┬──
       0   0.3  0.6  1.0  atr_pctile                  0   0.4  0.7  1.0  atr_pctile
```

两条曲线在 `atr_pctile ∈ [0.6, 0.7]` 区间的行为差异最能体现设计意图:此时评分分量已过峰值开始回落(提醒"可能接近衰竭"),但仓位分量尚未开始衰减(不因此拒绝已确认的高质量信号,只是要求 P1 阶段验证该区间是否需要提前联动)——两者错峰而非同步收紧,避免"评分开始扣分 + 仓位同时缩水"的双重惩罚在同一区间叠加。
